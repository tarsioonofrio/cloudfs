Troubleshooting

Start with gdisk doctor: it checks everything and prints the fix for each problem.

Installing and mounting

“fusermount3 not found”. Install FUSE 3: sudo pacman -S fuse3 (Arch), sudo apt install fuse3 (Debian/Ubuntu), sudo dnf install fuse3 (Fedora), sudo zypper install fuse3 (openSUSE).

“/dev/fuse does not exist”. Run sudo modprobe fuse; reboot if it was just a kernel update.

“Transport endpoint is not connected”. A previous run left a dead mount. gdisk mount cleans it up; by hand: fusermount3 -uz ~/gdisk.

“already running”. gdisk status shows it, gdisk stop unmounts it. If you enabled start at login, the service started it.

Signing in

“Error 403: access_denied”. Your client is still in Testing. In the Cloud Console open Audience and press Publish app (or add yourself under Test users), then run gdisk login again.

“The app name does not comply”. The consent screen name contains “Google” or “Drive”. Change it under Branding.

“Google hasn’t verified this app”. Expected: Advanced → Go to … (unsafe) → Allow.

invalid_grant / “Session expired”. Run gdisk login again. If it happens every 7 days, publish the app (Audience → Publish app). It also happens after a password change or after revoking access.

The browser is on another machine. Open the printed address in a browser on the same computer, or forward the port shown in it over SSH.

Files

Uploads stay pending. gdisk status shows the pending count; the log says why (~/.local/share/gdrived/gdrived.log). They are retried and survive a reboot.

A big file is not on Drive right after I copy it. Files above 8 MiB are uploaded in the background, about 20 seconds after the last write, in pieces, so any size works. gdisk status shows dirty: N while uploads are pending; the file is readable from ~/gdisk meanwhile.

name (conflito …).ext appeared. The file changed on Drive while you edited it here. Your edit is saved under that name; the original shows the Drive version. Keep the one you want.

Google Docs/Sheets/Slides. They appear as small .gdoc files: open them in the browser, or run gdisk export FILE.gdoc --format docx.

I deleted something. It is in the Trash: mv ~/gdisk/Trash/file ~/gdisk/Photos/.

“Read-only file system”. Shared with me, Shared drives and Trash are views; copy files out of them.

Starting over

Check gdisk status shows dirty: 0, then gdisk stop, gdisk autostart disable, gdisk logout, rm -r ~/.local/share/gdrived ~/.config/gdrived, and gdisk setup. Nothing on Drive is deleted.
