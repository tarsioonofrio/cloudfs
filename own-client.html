Creating your Google client

Once, about two minutes. The same model rclone uses.

GDisk does not ship with Google credentials. You create your own OAuth client, which means no shared quota, no dependency on anyone else, and no Google review standing between you and your own files. The easy way: run gdisk setup. It shows these steps, opens each page in your browser, and checks what you paste. This page is the same thing with every screen described.

You need a Google account and a browser. Nothing here costs money.

1. Create a project

Open console.cloud.google.com/projectcreate (accept the Cloud Console terms if asked). Give the project any name (for example gdisk) and press Create. Make sure the project name at the top of the page is the one you just made: everything below happens inside it.

2. Turn on the Google Drive API

Open the Google Drive API page and press Enable. It worked when the page shows “API Enabled” or a Manage button.

3. Set up the consent screen

Open Google Auth Platform and press Get started:

  1. App information: any app name, but without the words “Google” or “Drive” (Google rejects them: “the app name does not comply”); gdisk is fine. Support email: yours.
  2. Audience: External.
  3. Contact information: your email.
  4. Finish: tick the agreement to the API Services User Data Policy, Continue, Create.

4. Publish the app

Open Audience, press Publish app, then Confirm. While an app is in “Testing”, Google expires the sign-in every 7 days. You do not need to send the app for verification: that is for programs distributed to the public.

5. Create the client

Open Clients → Create client: Application type Desktop app, any name, Create. A window shows the Client ID (ends in .apps.googleusercontent.com) and the Client secret (starts with GOCSPX-). Copy both.

Using what you copied

Run gdisk setup (or gdisk login) and paste them when asked. They are saved in ~/.config/gdrived/config.toml, readable only by you. In the window, the Set up button on the first screen asks for the same two values.

The one warning you will see

At sign-in Google shows “Google hasn’t verified this app”. That is expected: the “app” is the client you just created and you are its owner. Click Advanced, then Go to your app name (unsafe), then Continue/Allow on the page that lists “See, edit, create and delete all of your Google Drive files”. GDisk needs that permission because it shows your whole Drive as a folder; the login stays on your computer.

Questions

Is it safe to keep the secret in a file? For desktop programs Google treats the client secret as non-confidential (it is inside every such program). The file is readable only by you.

Another computer, or another account? Copy the ID and secret to the other computer. For another account use gdisk --profile NAME setup.
